## Requirements

| Component | Requirement | Purpose |
| --- | --- | --- |
| Python | `>=3.11,<3.12` | Benchmark runtime. |
| `uv` | Current release | Locked Python environment and dependencies. |
| Node.js and npm | Current LTS recommended | Documentation site only. |

## Benchmark Setup

From the repository root, create the locked Python environment:

```sh
make setup
```

`make setup` installs `uv` when needed and synchronizes the dependencies in `uv.lock`.

## Prepare Data

Dataset manifests in `data/manifests/` declare a pinned Hugging Face revision, split files, schemas, and checksums. Preparing a dataset downloads its raw files, validates them, writes the refined benchmark schema, and records refined checksums.

```sh
make prepare DATASET=calit2
```

Run the individual stages when needed:

```sh
make ingest DATASET=calit2
make refine DATASET=calit2
```

Prepare every manifest with:

```sh
make prepare-all
```

Raw and refined files are local artifacts under `data/raw/` and `data/refined/`; they are not committed to Git.

## Run Experiments

Experiment definitions in `experiments/` select a dataset, model, protocol, threshold selector, parameter candidates, and metric settings.

```sh
make train EXPERIMENT=calit2-pca-inductive
```

Training evaluates every configured parameter candidate on validation data, selects a threshold from validation scores, and creates a validated run artifact.

```sh
make evaluate EXPERIMENT=calit2-pca-inductive VALIDATED_RUN=<validated-run-id>
```

Testing applies the selector calibration without using test labels. Fixed selectors reuse their numeric validation threshold, while adaptive selectors derive a test threshold from persisted validation calibration and test scores. Inductive models restore the selected fitted model; transductive models instantiate a new model and fit/score the complete test feature batch according to their protocol.

Run both phases together:

```sh
make run EXPERIMENT=calit2-pca-inductive
```

## Visualize Runs

After test artifacts exist, export the interactive run data:

```sh
make visualize
```

This writes `docs/public/runs.json`. The documentation site uses it for its run comparison and explorer pages.

For saved runs containing `training_history.json`, `make visualize` writes an interactive `training.html` beside that file and exposes it through an **Open training diagnostics** link in the run explorer. Historical MaxEnt-PCA runs can contain this history; new fits record only final diagnostics, not periodic monitoring or training charts.

## Quality Checks

Run the benchmark checks from the repository root:

```sh
make format
make lint
make test
```
